# skill-guide-writer — Quality Rubric

## 证据与可追溯性

- [ ] 关键结论是否能追溯到本地文件、命令输出或已核验网页？
- [ ] 若本地文件与网页都被使用，是否明确了谁是主依据、谁是补充？
- [ ] 若存在推断 / 建议，是否显式标注，而不是伪装成事实？

## 覆盖度

- [ ] 是否说明了适用对象与前置条件？
- [ ] 是否至少提供了一个最短成功路径？
- [ ] 是否覆盖了关键参数或关键输入？
- [ ] 是否解释了与相邻技能/工具的边界？

## 结构与可读性

- [ ] 若包含 L2，第一段是否先给出最短成功路径？
- [ ] 是否按“先上手、后细节”的顺序组织内容，而不是先铺背景？
- [ ] 组合层级时，是否避免了重复示例和重复段落？

## 可操作性

- [ ] 示例是否可直接复制，且不依赖隐含上下文？
- [ ] 示例参数是否贴近真实场景，而不是 `foo/bar/test`？
- [ ] 错误修复步骤是否具体到“下一步做什么”？
- [ ] 若仓库里已有真实命令 / 路径 / 参数名，是否直接复用而不是抽象改写？

## 一致性

- [ ] 触发词、参数名、输出字段是否与现有文件一致？
- [ ] 文中是否混淆了“事实”和“推断”？
- [ ] 是否避免承诺当前未验证的能力？
- [ ] 若要求落文件，是否沿用了仓库现有文档目录或命名风格？

## 增量更新

- [ ] `[NEW]` / `[CHANGED]` / `[DEPRECATED]` 标记是否只用于真的变化？
- [ ] 更新后的全文是否仍然可独立阅读，而不是依赖旧版上下文？
- [ ] 若信息不足，是否用 `> ⚠️ 待确认` 明示，而不是留下“待补充”占位符？
