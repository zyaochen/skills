# skill-guide-writer — Output Levels

## 默认策略

- 未指定层级：输出 **L2 + L3**
- 用户说“简短 / 概要 / one-pager”：输出 **L1**
- 用户说“完整 / 详细 / developer reference”：输出 **L2 + L3 + L4**
- 用户只要“升级说明 / 变化点”：至少输出 **L2 + 变更摘要**；若涉及内部结构或迁移，再补 **L4**
- 用户要求落文件时，层级不变，只改变交付介质

## 组合规则

- 组合层级时，输出应是一份**单文档**，不要按层级机械重复内容
- 包含 L2 时，第一段必须先给**最短成功路径**
- L2 负责“第一次跑通”，L3 负责“日常使用与边界”，L4 负责“维护与扩展”
- 同一个示例够用时，不要在 L2/L3 重复贴两份几乎相同的命令

## L1 — One-pager

适合决策者或第一次了解能力的人：
- 一句话价值主张
- 3 个典型场景
- 1 个最短示例
- 与替代方案的差异
- 能做什么 / 不能做什么

## L2 — Quick Start

适合第一次上手：
- 第一段先给最短成功路径
- 前置条件（权限 / 配置 / 依赖）
- 从零到第一次成功调用的最短路径
- 一个端到端示例
- 常见首次错误与修复
- 若需要路径、命令、参数名，优先使用本地真实名称

## L3 — Full Guide

适合日常用户：
- 功能分模块说明
- 每个模块至少 1 个可复制示例
- 参数说明表
- 触发条件 / 使用边界
- FAQ / known limits / 与其他技能的协作关系
- 若存在事实与建议混合的风险，显式分成两个小节

## L4 — Developer Reference

适合二次开发或维护者：
- 内部结构概览
- 扩展点与自定义方式
- 稳定契约 / 数据流
- 版本变化与 breaking changes
- 关键结论尽量回指文件、测试或命令证据
