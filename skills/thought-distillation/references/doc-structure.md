# 蒸馏文档骨架（张力驱动版）

第一版常见失败："图少、没有张力"——按主题罗列观点、只有表格和列表。下面的骨架以**冲突**为主线组织材料。

## 0. 定主线（先于一切写作）

1. 从各组笔记的"主线候选"里找共同的底层问题：他反复在回答什么？
2. 主线句必须包含**一对张力**，例如：
   - "放手与攥紧"：把执行交给 AI，把判断攥在手里
   - "追着瓶颈走"：模型每变强一次，瓶颈就迁移一次
3. 检验：随机抽 5 篇文章，能否各自归到主线的某一幕？不能就重想。

## 2. 张力写作手法

- **标题即冲突**："Coding 从来不是瓶颈""50 年前的设计打败了去年的新协议""人可以被说服，Linter 不会"
- **先旧后新**：每幕先立靶子（旧共识，可以包括"去年的他自己"），再推翻
- **给出代价**：他踩过的坑、他自己的反例（如"抛弃 MCP"却天天用某个 MCP）
- **抓自相矛盾**：两篇文章观点相反时不抹平，摆出来并给调和（标注"本文推断"）
- **读者信号**：阅读量最高的几篇往往恰好落在主线两极，可作佐证
- **反方要真打**：不写稻草人；承认样本小、预估多、依赖个人投入

## 3. 证据纪律

- 引号内=原文逐字；转引/翻译/推断显式标注
- 翻译类文章几乎没有作者评注时，只能作"选题信号"，不能当他的原话
- 数字标明"实测 / 预估 / 第三方"；口径不一致就写出来
- 别把书籍梳理、AI 生成的文章当作"思想出处"

## 4. 常见坑

- 只罗列观点，没有主线 → 回到第 0 步
- 把早期/生活文章标"低信号"跳过 → 恰恰是"根"
- 图只有 2–3 张流程图 → 至少 12 张，类型混搭
- 用已有蒸馏的视角写"我怎么读他" → 只写他的思想本身，差异单列
