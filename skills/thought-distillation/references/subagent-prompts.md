# 子代理提示词模板

通过 Task 工具启动 `generalPurpose` 子代理，**前台并行**（同一条消息里多个调用，`run_in_background: false`）。子代理看不到对话历史，提示词需自包含。

> JSON 参数注意：提示词中的 ASCII 双引号必须转义，优先用「」『』代替；参数对象只闭合一次 `}`。

## A. 精读笔记（每组 4–8 篇）

```
只读任务，不要修改任何文件。你在帮我蒸馏一位作者（<姓名/花名>，<身份一句话>）的思想，目标是提炼他『<蒸馏目标，如 AI 落地的思想与经验>』。请精读以下 markdown 文件（全文读完，大文件分段读）：<路径1>（<标题>）、<路径2>（<标题>）……

请用中文返回结构化笔记（<3000-6000> 字），每篇分别给出：
1. 日期与核心论点（1-2 句）；若是翻译，说明原作者，并区分他本人评注
2. 关键观点/判断（5-10 条，保留原话用引号）
3. 方法论/具体做法/架构（工具、配置、流程、数字）
4. 他反对什么/踩过的坑
5. 金句（原文逐字，3-5 句）
最后跨篇综合：一致立场、思想演进、主线候选（1-3 个）、内在张力/矛盾。不要编造，所有引用必须来自原文。
```

推荐分组：
1. 本质与范式（他对对象本质、人机关系的总论）
2. 工具 / 工程化 / 编排 / 安全
3. 知识 / 记忆 / 技能沉淀
4. 逆向 / 解读 / 翻译 / 作品展示（重点看思维方式与对厂商态度）
5. 业务落地文档 + 个人索引页（问题、方案、决策理由、量化结果、踩坑；索引页逐条列个人观点、投入、项目理念、经历）
6. 早期技术文与生活文（找"根"）+ 已有蒸馏的评估（主线、优点、遗漏/偏差）

## B. SVG 信息图（每个子代理 1–2 张）

```
你要为一份飞书文档设计 <N> 张 SVG 信息图（中文），用于飞书画板渲染。请先运行 `lark-cli skills read lark-doc/references/lark-doc-whiteboard.md` 阅读『画板 SVG 设计指南』并严格遵守（文字用 <text>；禁止 pattern/clipPath/mask/非阴影 filter；渐变用默认 objectBoundingBox；必须有 viewBox；要有设计感与视觉隐喻；CJK 文字按 1em 宽度留足空间）。设置 LARKSUITE_CLI_NO_UPDATE_NOTIFIER=1。
重要：不要用 Write 工具写 SVG（可能写坏中文），用 shell heredoc 或 python 以 UTF-8 写文件，并用 xmllint 校验。预览 PNG 可能把彩色/白色文字渲染为深色，属预览问题；深色底上少放关键白字。

图 1：<输出路径>.svg —— <标题>，宽约 <1200>。<结构/隐喻：天平、拔河、成对条形、仪表盘、气泡时间线…>。数据：<逐条列出，原文数字>。

验证流程（必须做）：在 <工作目录> 下用 `lark-cli docs +create --as user --content -` 创建标题为『SVG 草稿-勿用』的临时文档，内容 `<title>SVG 草稿-勿用</title><whiteboard type="svg" path="@./svg/xxx.svg"></whiteboard>`（path 只接受相对路径）；从返回 new_blocks 取 whiteboard 的 block_token，`lark-cli docs +media-download --type whiteboard --token <token> --output ./svg/xxx.png --as user` 导出，Read 查看，检查溢出/重叠/截断与美观；不满意就改，最多 3 轮。返回 SVG 路径、PNG 路径、是否正常。不要修改其他文件。
```

常用 SVG 题材：
- 主线天平 / 对称结构（两极各 5 项 + 支点 + 两端失败警示）
- 原文数据对比（成对条形 + 倍数徽章 + 结论条）
- 前后对比仪表盘（实验组 vs 对照组，脚注样本量）
- 张力拔河图（每行：观点 A ⟷ 观点 B ｜调和；未解决项醒目标注）
- 气泡时间线（阶段色带，气泡面积 ∝ √阅读量，转折点标记）
