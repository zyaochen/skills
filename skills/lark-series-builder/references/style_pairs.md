# 改写示例：同一个意思，怎么写才合格

每组“差”是子 Agent 常见的写法，“好”是合格写法。改写只换写法，不丢信息，不加没有出处的数字。示例里的数字和引用 key 只演示写法，写稿时一律换成 facts.md、refs.json、code_outputs.md 里有的。

## 章首

- 差：本章将介绍 NCCL 的通信算法，并进行详细的分析。
- 好：8 卡机内 all-reduce 的上限由最慢一跳的单向带宽决定，H100 上是 450 GB/s{{r:nccl_perf}}；本章用这条上限判断实测差在哪。

章首写判断，不写“本章介绍”。

## 空泛形容

- 差：使用锁页内存可以显著提升数据传输性能，大幅降低训练时间。
- 好：同一块 PCIe Gen5 x16 上，可分页内存的 H2D 实测约 21 GB/s，锁页内存约 47 GB/s（本篇 sim_h2d.py 输出）；后者还能和计算重叠，暴露的等待从 38 ms 降到 4 ms。

“显著”“大幅”换成数字和口径。

## 红线：不是 X 而是 Y

- 差：瓶颈不是计算，而是通信。
- 好：这一步里通信占了 40%，计算只占 52%，先处理通信。

## 红线：进行、完成了

- 差：对模型进行量化之后，推理完成了加速。
- 好：权重量化到 FP8 后，decode 每 token 读的字节减半，单卡吞吐从 1.0 倍升到约 1.7 倍{{r:fp8_report}}。

## 红线：一是、第一，

- 差：原因有三：一是带宽不足，二是负载不均，三是同步过多。
- 好：带宽不足、负载不均和同步过多都会拉长 all-to-all；先用 busbw 判断是不是带宽（第 3 章）。

需要并列时用列表或表格，正文里不数“一二三”。

## 破折号

- 差：分桶 overlap——也就是把梯度分成多块——可以隐藏通信。
- 好：分桶 overlap 把梯度切成多块，每块算完就发，通信因此藏到反向计算后面。

## 口径不清

- 差：NVLink4 带宽 900 GB/s，是 PCIe 的 14 倍。
- 好：NVLink4 每卡双向合计 900 GB/s，单向 450 GB/s；PCIe Gen5 x16 单向约 63 GB/s，单向对单向约 7 倍。

带宽、算力、延迟都写口径，比较时同口径。

## 自指链接

- 差：详见 {{C:21}} 第 4 章。（本篇就是 21）
- 好：详见第 4 章。

## 量词标题和口号

- 差：`<h2>4.2 调优三板斧</h2>`；“打通全链路，实现降本增效”。
- 好：`<h2>4.2 先查拓扑，再调 NCCL 参数</h2>`；“同样 64 卡，step 时间从 46 s 降到 37 s”。

## 误区 callout

- 差：💡 常见误区：不要盲目调参。
- 好：💡 <b>常见误区</b>：看到 GPU-Util 100% 就认为卡已经吃满。GPU-Util 只表示采样窗口内有 kernel 在跑，一个只占 1 个 SM 的 kernel 也能显示 100%。看 SM Activity 和 Tensor Core Active（DCGM）才能判断饱和度。

现象、原因、改法三样都要有。

## 本章要点

- 差：🔑 本章要点：本章学习了很多重要内容，希望对大家有帮助。
- 好：🔑 <b>本章要点</b>：ring all-reduce 的 busbw 上限等于最慢一跳的单向带宽；实测低于上限八成时，先查是不是跨了 PCIe。本章消掉的是“卡等卡”里由拓扑造成的那部分等待。

末句点明本章解决了主线上的哪一项。
