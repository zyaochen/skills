# 画图规范

目标：任何模型画出来的图都和样板库（`assets/gallery/`）一个水准。做法是三条：用 `svgkit` 的构件出图，不手调坐标；照最接近的样板改；`check` 清零后再看渲染图。

## 1. 每张图先写三行，再动手

```
判断：这张图要读者带走的一句话（会成为主标题）
图型：ledger / flow / bars / groups / lanes / compare / matrix / ladder / arch（见第 3 节）
数字：图里每个数字和它的出处（refs key 或 code_outputs 的命令），必须和正文一致
```

写不出“判断”的图不要画，正文一句话就够了。

## 2. 视觉规范（`svgkit` 已内置，手写元素也要遵守）

- 画布宽 1200，高 400 到 960。省略 `h` 时 `svgkit` 按内容自动定高，优先省略。
- 主标题 x=40、y≈58、28px 加粗，写判断句，一行放得下（约 38 个汉字以内）。例：“哈希极化让一半上行链路空着”，不写“ECMP 对比图”。
- 副标题 y≈92、14px 灰字，一句话说明怎么读：横轴是什么、颜色代表什么。
- 内容从 y≥120 开始，到来源行上方至少 52px 结束。
- 底部“来源：”12px：论文名加表号、厂商页面、“本篇 sim_xxx.py 输出”。没有外部来源写“来源：本文整理”。
- 色板只用 config `board.families` 的五个色系加中性灰。用色有语义：主角蓝、对照橙、正向绿、风险红，第五类才用紫，背景和基线用灰。一张图最多三个色系（灰不算）。
- 字号：标题 26 到 30，面板小标题 18 到 20，正文 14 到 16，注释、轴标签、来源 12 到 13。不小于 12。字放不下就缩短文字、换行或加高画布，不缩字号。
- 面板浅底加同色边框，圆角 12；并列对比用白底色边。连线用正交折线，箭头手画三角。条形后垫 #F2F3F5 底槽，数值标在条形右端。
- 不用深底浅字（渲染器可能把浅色字画成黑色），标签一律浅底深字。
- 禁用 `filter radialGradient pattern clipPath mask image script marker foreignObject` 和 rotate/skew/matrix 变换。文字里不写 `<`（文档层会截断 SVG），小于号写“＜”或“小于”。公式用 Unicode（√dₖ、Σ、≈、×、→）。
- 图里不写“图 3”这类图题。同一张图在一篇里只放一次。
- 不为了塞下而截断词（把“隐藏”写成“隐”）；放不下就换行或换构件。
- 内容要铺满画布宽度：表格用 `table()` 默认的 `fit=True` 拉满，左右两侧各留 40px，不要只占左半边。

## 3. 图型目录（先选型，再打开对应样板照着改）

| 图型 | 什么时候用 | svgkit 构件 | 样板 |
|---|---|---|---|
| ledger | “时间或成本花在哪”，以及优化前后各项怎么变 | `stack()` 两条，第二条按总量等比缩短，加 `note()` | `gallery/ledger.py` |
| flow | 方法、流水线、决策流程，3 到 6 步 | `flow()`，回环用 `arrow()` 折线，下方 `card()` 写产出 | `gallery/flow.py` |
| bars | 实测离上限多远、几个方案比大小 | `bars(..., ref=(上限, '标签'))` | `gallery/bars.py` |
| groups | 几种负载 × 两三个方案，共用一把刻度 | `groups()`，绝不用多次 `bars()` 错位排布 | `gallery/groups.py` |
| lanes | 重叠、流水线、气泡、串行等待 | `lanes()` 两组（改前、改后），组标题用加粗 `text()` | `gallery/lanes.py` |
| compare | 一个改动翻转了机制：改前、改后 | `cols(2)` 两张 `card()` 加箭头，`tag()` 写复测数字 | `gallery/compare.py` |
| matrix | 选型、方案对照 | `table(..., hl={推荐行: 'green'})` | `gallery/matrix.py` |
| ladder | 分层、阶梯、量级落差 | `bars()` 加每行注释，下方两张 `card()` 给对策 | `gallery/ladder.py` |
| arch | 拓扑、架构、组件关系 | `cols()` 分栏，`card()` 当容器，`tag()` 当成员，带标签的 `arrow()` | `gallery/arch.py` |

每篇至少用到三种图型，不要整篇都是卡片加箭头。导读放一张总览（多用 ledger、ladder 或 arch），第 1 章一张“问题在哪”（多用 ledger 或 lanes），其余放在它解释的段落之后，大约一章一张。

## 4. 出图和自检

```python
import sys; sys.path.insert(0, '<skill>/scripts')
from svgkit import Board
b = Board('判断句主标题', '怎么读', src='来源：……')
y = b.stack(40, 170, 1120, [('计算', 620, 'blue'), ('等通信', 210, 'orange')], unit=' ms', title='优化前')
y = b.note(y + 28, '读者要带走的一句话', fam='blue')
b.save('figs/name.svg')        # 打印 OK 或问题清单
```

- 构件都返回自己的底边 y，下一个构件从 `y + 间距` 开始（标题行与内容 24 到 40，组与组之间 40 到 64）。
- `b.save()` 打印 `E`/`W` 问题。`E` 必须清零。`W` 多数是真问题（文字压字、出框、色板外颜色、字号过小），改到清零；确认是误报的要在回报里写出那条的原文和理由。“空带”“只占左边”“侧边距”三类永远不是误报。
- 检查器只管几何，不管意思：改完把图里每句结论和数字再对一遍（例如“TE 和 BW 达标”时，同样达标的 DS 不能漏掉）。
- 然后 `python3 <skill>/scripts/preview_local.py figs/name.svg`，用 Read 看 `figs/name.png`。按第 5 节清单逐条看，不合格就改，最多三轮。
- 发布后再看 `drafts/NN/pv/figXX.jpg`（飞书渲染，字体和本地不同），有溢出、截断再改。

## 5. 看图清单（自检和评审共用）

1. 主标题是一句判断，不看正文也知道这张图要说明什么。
2. 一眼能找到主角（蓝色或最长的那条），颜色语义和正文一致。
3. 文字不压字、不出框、不碰画布边，连线不穿字。
4. 对齐：同类元素左边或中心对齐，间距一致；没有大片空白，也没有挤成一团。
5. 图里每个数字都能在正文或 code_outputs 里找到，口径一致。
6. 来源行写清出处。
7. 删掉任何一个元素都会丢信息；装饰性元素（无意义的图标、渐变、阴影）一律不要。

## 6. 修已发布的图

整篇覆盖发布时旧画板 token 会丢，所有图都从 `figs/*.py` 重新生成。修图只改 `.py` 再运行，不手改 `.svg`，保证图和数字能随代码输出一起再生成。数字改了以后用 grep 在 `figs/*.py` 和 `seg/*.xml` 里查旧数字，确认一处不剩。
