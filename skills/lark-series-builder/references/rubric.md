# 评审打分表

由独立的评审 Agent 打分（不能是写这篇的 Agent），评审只读不改。机器检查（lint、stats、svgcheck）管得住格式和数量，这张表管机器看不出的质量。

**过线条件**：每一维不低于 4 分，正文七维平均不低于 4.2。没过线的篇进入 polish 轮，按评审给的修改单改，最多两轮；两轮后仍不过线的维度写进主编回报。

打分要求：每一维给分时必须引用原文（不超过 50 字，能 grep 到）作证据，并给一条具体修改（改哪个文件哪一处、改成什么方向）。给 5 分也要给证据。拿不准时就低给分，不要高给。

## A. 正文七维

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| A1 论点 | 每章开头一两句就是判断；导读每条都能单独转述 | 部分章节开头是“本章介绍” | 通篇罗列，看不出主张 |
| A2 厚度 | 每章都有机制、3 个以上带口径的数字、可照做的命令或配置、边界条件 | 一半章节只有概念和结论 | 大量“显著”“大幅”，几乎没有数字和操作 |
| A3 证据 | 每个具体数字都有引用或代码输出，前后数字一致，厂商口径写清 | 少数数字缺出处或口径 | 数字和引用对不上，或有明显错误 |
| A4 主线 | 主线位置段、每章要点末句、闭环案例都在，和前后篇衔接自然 | 主线元素齐但生硬，像贴上去的 | 和系列主线无关 |
| A5 文风 | 句子干净，先结论后依据，术语有中文说明，无口号 | 有长句、套话，个别段落啰嗦 | 翻译腔、口号、Markdown 残留 |
| A6 实用 | 读者照着能做：命令、指标名、阈值、核对清单、自测题齐全 | 有清单但条目空泛 | 读完不知道下一步做什么 |
| A7 边界 | 只深挖本篇 scope，相邻内容一句话指向别篇，不重复 | 有一两章越界或和别篇重复 | 大段讲别篇的内容 |

## B. 图四维（每张图打，取最低分）

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| B1 判断 | 主标题是一句判断，图只讲这一件事 | 标题是名词短语（“X 对比”） | 没有标题或一张图讲三件事 |
| B2 版面 | 对齐、留白均匀，无压字、出框、大片空白 | 小的不齐或局部拥挤 | 文字重叠、截断、出画布 |
| B3 选型 | 图型匹配信息（拆账用 ledger、重叠用 lanes…） | 能看懂但图型别扭 | 用卡片堆砌本该是条形或时间线的数据 |
| B4 一致 | 数字和正文、code_outputs 一致，色彩语义统一，来源写清 | 少量数字口径不清 | 数字和正文矛盾 |

## 输出格式

只输出 JSON，不加别的文字：

```json
{
  "doc": "05",
  "scores": {"A1": 4, "A2": 3, "A3": 5, "A4": 4, "A5": 4, "A6": 3, "A7": 5, "B1": 4, "B2": 3, "B3": 4, "B4": 5},
  "mean_A": 4.0,
  "pass": false,
  "fixes": [
    {"dim": "A2", "where": "seg/s04.xml 4.2 节", "evidence": "原文引用", "fix": "补 X 的机制和 Y 的实测数字（code_outputs 第 3 条）"},
    {"dim": "B2", "where": "figs/tma.py", "evidence": "图例压在第三根条形上", "fix": "图例移到条形组上方，画布加高 60"}
  ]
}
```

`fixes` 最多 12 条，按影响从大到小排；每条都要能直接交给 polish Agent 执行。
