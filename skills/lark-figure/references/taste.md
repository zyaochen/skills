# 审美规则：每一条都已经写进代码

这份文档解释排版引擎为什么这样排。规则的数值都在 `assets/theme.json`，算法在 `scripts/lfig/`。改风格改 theme，改布局改引擎，不在单张图上手调。

## 1. 一张图一个判断

- **主标题是结论**。读者扫一眼标题就该知道你要说什么，图是证据。“排队占了 60% 的时间”能被引用、能被反驳，“请求流程图”不能。lint 对 8 字以内或以“架构图/流程图/概览”等结尾的标题给 `TITLE-LABEL` 提示。
- **副标题告诉人怎么读**：颜色代表什么、数字是什么口径、轴是不是对数。
- **来源永远在左下角**。数字可追溯是可信度的底线；没有外部出处写“来源：本文整理”。
- 标题一行放下，28px 放不下自动降到 24px，再放不下就报错让你缩短：长标题意味着判断没想清楚。

## 2. 版式

| 项 | 值 | 原因 |
|---|---|---|
| 画布 | 宽 1200，浅底 `#FAFBFD`，描边 `#DEE0E3`，圆角 16 | 嵌在飞书文档里和白色正文区分开，又不抢眼 |
| 左右边距 | 40 | 标题、正文、来源左对齐在同一条线上 |
| 标题 / 副标题基线 | 58 / 92 | 固定位置，系列文档里所有图的标题都在同一高度 |
| 正文起点 | 128（无副标题 100） | 标题区和内容区之间留出呼吸 |
| 底部 | 来源基线距底 24，内容距底至少 64 | 来源不贴内容 |
| 最小高度 | 420，内容不够时按 4:6 光学居中（上少下多） | 几何居中会让内容飘在标题和来源中间，离开它要证明的那句话 |

### 2.1 spec 可以撬动的两个版式维度

- **`aspect`**：画布宽取值 `narrow=1000` / `normal=1200`（默认）/ `wide=1300`。宽画布给"宽表 + 4 张并排卡"；窄画布让 viewBox 更接近 1:1，服务端 square-fill 后空白更小。lint 的 `SIZE-WIDTH` 接收这四个 house 宽度。
- **`density`**：compare/table 行高因子 `compact=0.8` / `normal=1.0`（默认）/ `airy=1.15`。用途是"内容多 / 想少占纸面"，不是"让字变小"——字号不变，只动行高。
- 高度超过 `max_height=1100` 直接 SpecError，不再静悄悄产出超出 frame 的 SVG。报错总会建议拆图；`density: "compact"` / `aspect: "narrow"` 只在引擎试排后确认能把这张图压回上限内时才列出（`density` 只影响 compare / table）。

### 2.2 editorial 风格开关

- **`title_align: "center"`**：title 和 subtitle 从默认左上改为画布水平居中。配合 `frameless` 是演进 / 生命周期类图的标志。
- **`frameless: true`**：跳过 frame rect（外框 + 浅底），整张图漂浮在文档白底上，跟文字融为一体。
- **`footline.dashed: true`**：footline 从实线结论横幅换成虚线"小总结"分隔条（参考 Aime 演进图 / 商家生命周期图的中段 dashed 长框）。
- 这三个的组合（center + frameless + dashed footline）是「editorial infographic」的标准配方，对应参考文档 LLM 系列里里程碑和演进类图。

## 3. 颜色

- 只用飞书色板的 5 个色系加一组中性灰。每个色系 5 档：深字（只给文字）、主色（条形、强调边框）、边框、浅底、更浅底。
- **语义固定**：主角蓝、对照橙、正向绿、风险红、第五类紫、背景灰。读者看过一张就会读下一张。
- **先灰后彩，够用就不加**。不写 `tone` 的元素是灰的；一般的图 1–2 个彩色系就够，颜色是用来区分的，种类一多就没有区分度了。只有每张卡各是一类（版本演进、模块并列，见 3.1）时才一卡一色，上限是色板的全部 5 个彩色系（`theme.json` 的 `max_families`）。
- **浅底深字，不反白**。飞书画板可能把浅色字渲染成黑色；深底白字在文档里也太重。
- 强调靠“浅底 + 同色系主色描边 2px”，普通块是“更浅底 + 同色系边框 1.5px”。白卡片只用在需要并排比较的场合，同一行的东西看起来是同一类。
- 图例色块和它解释的块用同一套软边框（同色系边框 1.5px，虚线块配虚线色块），图例和图上看起来是同一个东西。

### 3.1 tone 是信号灯，仅在「同 category」时不当分类器

- **同 category 多卡**（三个并行实现 / 三种并行切法）：同 tone（典型全 `base`），对比靠 `id`(①②③)、`icon`(✗/✓)、`verdict` 文字。lint 用 `COLOR-OVERUSE`（饱和元素 > 25）和 `TONE-AS-CLASSIFIER`（同 family ≥ 15 个饱和元素）拦过量上色。
- **异 category 多卡**（版本演进 / 新旧方案 / 模块并列）：**列卡异色是合法的**。每张卡一个 family，引擎自动把卡片本体 pale wash 成 `families[tone].bg2`（饱和度 < 10%），彩色面积仍小。这就是参考文档 LLM 系列（如 Aime 1.0→3.0 演进图）的实际做法。
- **灰色家族 bg/bg2 有方向**：`gray.bg = #F5F6F7`（外层嵌套底），`gray.bg2 = #FFFFFF`（内层、需要浮现的面）。一旦嵌套，内层一定比外层浅，视觉上才是“浮起来”而不是“沉下去”。
- **highlight / primary 只开一道顶部 colorline**（3px 主色），不再整卡描边。colorline 只占顶边的直线段（两端各让出一个圆角半径），不会戳出圆角。
- 需要把“这是对比组”说 stronger 时，用 `card_style: "outlined"`（白底 + 主色描边），不要退回整卡 bg。
- **1 张图最多 1 张 primary 卡**。lint 用 `PRIMARY-DUPLICATE` 拦多张 colorline 同图。
- **结论横任选 1 条**：`callout`（顶部）或 `footline`（compare 底部），不同时上。

## 4. 字

| 用途 | 字号 | 字重 |
|---|---|---|
| 主标题 | 28（24–30） | 粗 |
| 卡片标题 | 20 | 粗 |
| 面板小标题 | 18 | 粗 |
| 正文、标签 | 14 | 常规 |
| 注释、轴、来源 | 12–13 | 常规 |
| 关键数字 | 26 | 粗、同色系深字 |

- 12px 是下限，lint 报 `FONT`。
- 行高 1.55 倍。
- 文字宽度按画板自己的量法估：中文常规 1.06em、粗体 1.2em，拉丁字母按大小写、数字、窄字宽字分档，粗体再乘 1.27。这组系数是用 whiteboard-cli 实测拟合的；只按“中文 1em、英文 0.6em”估，粗体标题会被画板判溢出。
- 换行时标点不出现在行首，左括号不留在行尾，英文单词整词换行。
- 段落不以孤字收尾：末行不足两个汉字宽、而上一行让得出一个词时，把那个词挪下来；行数不变。

## 5. 线

- 连线只走水平和垂直（正交折线），箭头是手画三角形，不用 `marker`：画板对 marker 的支持不稳定。
- 箭头线在三角形底边截断，线头不会从箭尖戳出来。
- 线的颜色是中性灰 `#8F959E`，结构线（树的连线、里程碑竖线）更浅 `#C9CDD4`。重点靠块的颜色，不靠彩色线。
- 线不穿字。lint 的 `CROSS` 会查每一段线是否经过文字；被不透明色块挡住的线不算（例如甘特图里的标记线在色块下方）。

## 6. 各图型的取舍

- **graph**：节点顺序完全由 spec 决定（阶段从左到右，阶段内从上到下），引擎不重排；但每个节点会上下滑动去对齐它在相邻阶段的上下游（保序、保间距），让主链箭头尽量是一根直线而不是 Z 形小台阶——对齐后比居中排布高出 2 行以上才退回居中。对不齐时相邻阶段的连线在列间走正交折线，同源或同目标的折线共用一根主干；**跨阶段的 skip 走"上出上入"**（从源节点顶部垂直向上 → 共享 lane 水平 → 目标节点顶部垂直向下），三段折线、两个弯，看起来像一座桥；lane 必须高出途经的每个节点 26px，绝不从节点背后穿过；出口在源节点偏右、入口在目标节点偏左，一个节点既收一条旁路又发下一条时两根竖线不挤在一起；x 区间重叠的 lane 才错层；**回写走底部**，同样 bottom bridge。skip 边建议 `dashed: true`，把跨 stage 的大跨线降级成参考注脚。连线标签只放在自己那条线旁边的空位，放不下就报错，不会压线。
- **sequence**：参与者等距，消息标签从发送方一侧起排、不跨过任何生命线；返回是虚线，自调用是一个小回折。不画 alt/loop 框：需要的话用分段标签把阶段分开。
- **cycle**：上排从左到右、下排从右到左，首尾两根箭头把环闭上；步骤数是奇数时下排错开半格。中间那句话是这个环在推动的指标。
- **flow**：卡片等宽等高；超过 5 步自动折成两行，折返线走行间空隙。指标数字用 26px 色系深字，比文字更先被看到。
- **layers**：每层一条横带，左侧层名，右侧模块按内容宽度流式换行。一行里所有模块都放得下时等宽，所以模块数相同的层共用同一组竖边；放不下才按内容宽度拉伸填满。横切能力（可观测性、安全）放右侧竖条，条目紧跟标题往下排，不在竖条里垂直居中；side.items 支持两种形态：纯字符串（一枚 chip）或 `{label, value, tone?}`(label 灰字 + value chip 的键值对）。
- **compare**：所有卡片同高、同一组行，值右对齐，读者横着扫就能比较。卡片样式按 tone 自动：tone=base 时白底 + #C9CDD4 1.5px 边；tone≠base 时整卡 pale wash 成 `families[tone].bg2` + 同一边（这就是 R1 列卡异色）。推荐那张通过 `primary: true`（或旧字段 `highlight: true`）顶部加一道 3px 主色 colorline；行内 value 带 tone 时右侧出 chip。需要 explicit 区分对比组时，可以加 `id: "①"` 圆形编号 / `icon: "✗"` 标题前缀 / `card_style: "outlined"` 白底彩色描边。卡片下方可以加一条 `footline: {label, text, tone?}` slim banner 收束 takeaway，与 callout 只能选一条。`verdict` 胶囊挤到标题换行时，副标题跟着标题文字左对齐（不压到编号下），分隔线也随之下移。
- **bars**：横向条形，标签在左、值写在条尾，不画坐标轴；底槽贯穿整行。目标线遇到数值标签自动断开。
- **timeline**：泳道等高，色块里放得下才写字（先降到 tiny 字号），放不下就以灰色小字写在色块旁边的空泳道上（避开 marker 线，甘特图惯例），两侧都没位置才丢弃并在 notes 里告诉作者；时间轴在下方，单位放在箭头后面。色块一律用同色系软边框，只有 `emph: true` 的那一段（关键路径）用主色 2px 边；图例颜色必须和色块实际颜色一致。
- **matrix**：两轴只写名称和高低两端，不画刻度；目标象限整块高亮，其余三格默认 `base`，不要四格四色。
- **table**：数字列居中。表头行永远是中性灰底；强调列（行）是表格自身的一条色带：表头格用浅底、正文格用更浅底，压在网格线下面并顺着表格圆角，不再是盖在表头上的一个框。
- **line**：系列名直接标在线尾，不用图例框；数据点标签在 6 个候选位置里找第一个不碰线、不碰其他标签的位置，找不到就不标。
- **roofline**：双对数坐标，两轴只标整十倍刻度。屋顶线由 `peak` 和 `bandwidth` 算出来，拐点落在 `peak / bandwidth`，不接受手画的折线；第一条屋顶是实线参照，其余默认虚线。点不能高过最高的那条屋顶，坐标跨度超过 8 个数量级时报错而不是硬压。屋顶名写在图上方的图例行，拐点和算子名在点旁找不压线、不压其他标签的位置。
- **milestones**：超过 4 个事件时卡片上下交错；两端的卡片向内收，避免伸进边距。卡片统一宽度 = 最宽那张的内容宽 + 内边距（下限 176），不再一律撑满 300px。
- **tree**：从左到右，父节点对齐子节点的中线。多出来的宽度先给列间距（至多 160），再给窄的列（至多 200），剩下的才是两侧留白。连线是细的结构线，没有箭头：拆解关系不是流向。叶子不超过 16 个；每个叶子都带 `sub` 时放得下约 12 个，先碰到的是 1100 的高度上限。不写 `tone` 的树整棵是灰的，子节点继承父节点的 tone。

## 7. 什么时候不用这套

- 类图、思维导图、带 alt/loop 嵌套框的时序图：Mermaid 更合适，交给 lark-doc 的 `<whiteboard type="mermaid">`。
- 插画、UI 原型、地图：不在本技能范围，或者走 `freeform.md` 的手写通道，但同样要过 lint。
