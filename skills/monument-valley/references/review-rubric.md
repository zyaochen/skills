# 独立评审评分表

出图的模型给自己的图打分，几乎总是「通过」。本表把审美判断拆成五个可打分的维度，由**未参与出图**的评审执行，并用对照样本校准每一批评审，让换一个 agent 或模型时，验收下限仍然一样。

## 先后顺序

1. **机器度量**：`analyze_images.py metrics`。色板或比例 `fail` 的图直接重做，不送评审，省评审预算。
2. **准备评审材料**：
   - `analyze_images.py sheet` 生成带编号的整图接触表，每张最多六幅；
   - `analyze_images.py crops` 生成主角特写接触表，本相与画面清晰度看特写；
   - `analyze_images.py canary` 从一张已验收图生成对照样本（主角放大到必然超比例），**不告诉评审哪张是对照**，和一张已验收的基准图一起混进这批。
3. **独立评审**：按下文打分；`review` / `unmeasured` 的图由评审顺带给出主角框。
4. **校准本批**：对照样本 scale 必须低于下限、基准图五项必须全部达标，这批评分才有效；否则换评审重来，不要挑着采信。
5. **复测与记录**：有主角框的图带 `--boxes` 重跑度量；批次写进 `review_batches`，每张图的结论与分数写进 `images[].metrics` 和 `images[].review`。

## 谁来评

- 优先：宿主可用的子代理，且模型不同于出图时编排提示词的模型；单次调用，不接续出图对话。
- 其次：同一模型的全新子代理，不给它看出图对话。
- 都不可用：交给用户评，或在交付里写明「未经独立评审」，manifest 不置 `independent_review`。
- 自评不算：`reviewer` 与 `generator` 相同，检查器判不通过。

## 给评审什么，不给什么

给：接触表、主角特写、全尺寸的问题图（按需）、主角参考图、`appearance_anchor`、`identity_traits`、`scale_rule`、色卡与风格参考图、本评分表与 `aesthetic-canon.md`。图片以文件路径交给评审、让它用自己的读图工具打开，比作为附件转发更可靠。

不给：出图提示词、生成过程、上一轮评分、哪张是对照样本、「这些图已经改过好几次」之类的上下文。评审只回答画面是否达标，不评价提示词写得好不好。

## 五个维度

每项 1–5 分，整数。下限：identity 与 scale 不低于 4，其余不低于 3；任一项低于下限即整张 `fail`。

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| identity 本相 | 陌生人一眼说出它是什么（土豆就是土豆）；外观锚点全在 | 能认出是同一角色，但本相含糊（像蛋也像土豆） | 被认成别的东西，或出现第二个主角 |
| scale 比例 | 符合比例规则，与门洞、台阶、人群的相对大小自然 | 略偏大或偏小，但不喧宾夺主 | 主角成了画面主体，或小到找不到 |
| style 风格 | 与风格参考图同一画风：等距视角、低饱和、柔和长投影、留白 | 画风接近，但有局部高饱和、写实材质或透视不统一 | 换了一种画风（写实、赛博、水彩等） |
| clarity 画面 | 干净，无多手多脚、错字、伪文字、残影、拼接痕、像素化 | 有一处不影响阅读的小瑕疵 | 有明显畸形、乱码文字、像素化或破图 |
| narrative 叙事 | 场景隐喻与本关内容对得上，入口与出口可读 | 场景好看但与本关关系弱 | 画面与章节无关，或暗示了来源不支持的事实 |

打分对照 `aesthetic-canon.md` 的条款：每条的「检查」一栏写明它归哪个维度。任一维度低于 5 分时，notes 要写出违反的条款编号，例如「style 3：L1 光向与前几张相反，F1 有透视汇聚」。只写「感觉不对」的低分不算有效评审。

## 评审输出

每张图一段 JSON，整批放在一个数组里：

```json
{
  "image": 3,
  "reviewer": "<评审的模型或子代理标识>",
  "scores": {"identity": 5, "scale": 4, "style": 4, "clarity": 5, "narrative": 4},
  "verdict": "pass",
  "seen": "主角站在拱门下，左手扶着栏杆",
  "box": null,
  "notes": "最低分的原因与违反的条款编号，如「scale 4：H2 主角略大于门洞」；五项全 5 时可留空"
}
```

- `seen` 必填：写一处这张图里具体可核对的细节（背景物件或姿势）。编排方抽查几条；对不上说明评审没看清，整批作废。
- `box` 在度量为 `review` / `unmeasured` 时必填：`[x0, y0, x1, y1]`，0–1 相对坐标，框住主角身体（不含投影）。
- `verdict` 只能是 `pass` 或 `fail`，由分数下限决定，不另凭感觉。
- 看不到图时，评审只返回 `[{"error": "images_not_visible"}]`，不许猜分。收到这条就换一种传图方式或换评审。

## 批次记录

```json
{
  "id": "batch-1",
  "reviewer": "<同上>",
  "images_visible": true,
  "canary_scale": 2,
  "anchor_scores": {"identity": 5, "scale": 4, "style": 4, "clarity": 5, "narrative": 4}
}
```

检查器要求：`images_visible` 为 true；`canary_scale` 低于 scale 下限；`anchor_scores` 五项全部达标；每张图的 `review.batch` 指向一个通过校准的批次，且评审人一致。

## 分歧怎么处理

- 度量 `fail`、评审高分：以度量为准重做。度量只查底线，底线不过，分数再高也不算。
- 色板度量 `review`：评审 style 不低于 4 才算通过，否则重做。
- 度量 `pass`、评审低分：以评审为准重做，并在 notes 记下原因。
- 两位评审结论相反：按较低的分数处理，或交给用户裁决；不取平均数抹平。

重做时只改评审指出的问题，保持其余一致；同一张图三次仍不过，停下来把接触表和分数交给用户决定。

## 为什么要这样做（2026-09 跨模型盲评）

用两种不同模型的子代理，对同一批 22 张已验收图与两张埋入的反例（主角放大、主角变成蛋形）盲评：

| 观察 | 对应规则 |
|---|---|
| 图片以附件转发时，一个评审实际看不到图，却返回了一整套分数 | `seen` 必填、`images_not_visible` 出口、`images_visible` 批次字段 |
| 同一批图，一个评审整体偏严（多项 2–3 分），另一个接近度量 | 对照样本加基准图校准每一批，而不是信任某个模型的尺度 |
| 看缩略接触表时，评审分不出蛋形反例；换成主角特写后，同一评审给蛋形 identity 3、其余 4–5，并指出一张像素化的图 | 本相与清晰度看 `crops` 特写 |
| 两位评审都认为 6 张已验收图主角偏大，而这些图的高度比都在度量范围内 | 度量只挡极端；相对场景的比例由评审判断，不要用度量代替 |
