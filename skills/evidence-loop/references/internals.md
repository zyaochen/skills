# 内部实现与工程加固

这一页写给维护者和想核实"裁判凭什么可信"的人。日常使用技能不需要读它，按 [SKILL.md](../SKILL.md) 的标准流程走即可。

## 1. 代码结构

入口 `scripts/evloop.py` 只负责转发，实现都在 `scripts/evloop/` 包里，全部只用标准库：

| 模块 | 职责 |
|---|---|
| `cli.py` | 参数解析与分派，异常统一转成退出码 |
| `judge.py` | 裁判命令：init / start / smoke / attempt / status / resume / verify / approve / relocate / doctor |
| `contract.py` | 封存的契约、只追加的尝试记录、原始日志、文件锁 |
| `runner.py` | 运行约定命令：独立进程组，超时时杀掉整组，留存原始输出 |
| `scenarios.py`、`gitops.py` | 场景纯逻辑；git 调用封装 |
| `constitution.py` | 项目宪法的加载、合并与封存 |
| `research.py`、`text.py`、`sources.py`、`rubric.py` | 研究 / 文档场景：L1 硬检查、来源快照、L2 细则评审 |
| `formal.py` | 形式化设计验证：检查清单校验、配置生成、检查器输出解析、摘要复用、运行时预检、交付包章节 |
| `tlc.py`（入口 `evloop_tlc.py`） | 检查器准备：下载钉死的版本并合并成自带社区模块的单个 jar，查找 Java 或下载 JRE，跑内置模型自检，失败时给出诊断 |
| `plan.py` | 跨会话计划 |
| `report.py`、`render.py` | 交付包、进度快照与图的渲染 |
| `evals.py`、`matrix.py` | 技能评测与跨模型矩阵 |
| `util.py`、`__init__.py` | 退出码、哈希、原子写等共享设施；版本号 |

发布包的根目录只放 `SKILL.md`、`scripts/`、`references/`、`assets/`。智能体侧的元数据放在 `assets/AGENTS.md`、`assets/openai.yaml`，安装方式见 [portability.md](portability.md)。单元测试与评测用例不随技能发布，放在开发仓库里，见 [evals.md](evals.md)。

## 2. 相比朴素实现的工程加固

**契约与记录**

- 契约带 `schema_version` 和封存哈希。手工篡改过的契约、比当前工具版本更新的契约，都会被拒绝加载。
- 运行目录有文件锁。两个进程同时操作同一个运行会直接失败，不会互相覆盖。
- `attempts.jsonl` 只追加写入。进程被杀留下的半行，下次读取时会被识别并隔离，不会让整个运行读不出来。
- 契约和报告都原子写入；超时时杀掉整个进程组，不留后台子进程。
- `--renew` 只在新契约写入成功后才归档旧契约。
- 项目宪法里的 `frozen` 与命令行合并，一起计入冻结哈希；宪法文件本身也按哈希封存。

**裁决**

- `attempt` 要求 HEAD 是最优提交的后代，防止在过期的基础上裁决。
- `--delta` 与 `--delta-pct` 互斥。
- 时间、尝试次数、token 三种预算统一裁决；快速预检先挡掉明显失败的尝试。
- 失败的尝试自带关键行摘要和日志尾部。`resume` 与 `--brief` 让上下文小的模型也能可靠接手。
- `attempt --commit` 支持"并行生成、串行裁决"。

**分场景检查**

- 修复场景：`verify` 做红绿检查，在临时 worktree 里检出基线源码，再跑一次冻结的测试，必须仍然失败，以排除假红。
- 开发场景：支持逐元素验收命令。
- 优化场景：支持次要指标护栏，以及"净删除代码且分数持平"的简化规则。

**研究 / 文档**

- 来源按内容哈希只读快照。论断逐字核对；编造引用和注入文本判无效。
- 内容相同的镜像来源只算一个独立来源。规格里的 `cite_numbers` 可以要求正文里每个数字都有出处。
- 细则评审先用好 / 差样本校准，按噪声判断是否回退。多数样本已低于通过线时提前停止，省下调用。裁判本身不调用任何模型。

**形式化设计验证**

- 检查器是自带社区模块的单个 jar，清单里没有旁路依赖，按 sha256 钉死，哈希不符就阻断。
- `init` 与 `doctor` 会预检 Java 版本下限和模型用到的模块。路径含非 ASCII 字符时自动补上 UTF-8 区域设置；检查器出错时附带可操作的诊断。
- 只认 `-tool` 输出里错误级别为 0 的完成消息，并且状态数必须大于 0。
- 配置由检查清单确定性生成。需求与性质双向覆盖；故障动作必须进入动作组合。
- 输入摘要不变时复用结果，变了就必须重跑。已 verified 的约定被回退会被拒绝。
- 结论措辞固定，证据边界随交付包一起展示。

**跨会话计划**

- 计划与状态都封存防篡改。`done` 必须有裁判证据。共有七种停止条件。
- 确认模式下，批准绑定计划内容；自动模式下，每条假设都留痕。
- 上一会话既没有 `plan done` 也没有 `plan fail` 就中断时，记一次失败，防止无限重来；下一会话的提示词会带上上次卡住的原因。

**评测**

- `scripts/evloop_eval.py` 加上开发仓库里的评测用例，提供可复现的技能评测。
- `scripts/evloop_matrix.py` 在本机的 `codex` / `claude` 命令行上跑带技能与不带技能的对照矩阵。
