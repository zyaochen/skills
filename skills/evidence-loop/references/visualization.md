# 可视化：让人随时看得懂进度

人不会去读 `attempts.jsonl`。可视化的目的，是让人在任何时刻用几十秒看懂：做到哪了、证据是什么、下一步是什么。

## 1. 三个时刻

| 时刻 | 给人看什么 |
|---|---|
| 澄清 | 约定草案；开发场景附现状图与蓝图的渲染页面 |
| 循环中 | `report --progress` 生成的进度快照 |
| 交付 | `report` 生成的 `handoff.html` 交付包 |

## 2. 只画实际状态

进度快照描述的是**已裁决的**状态：保留的提交、已认领的元素、记录在案的分数。工作区有未提交或未裁决的改动时，页面会明确提示"下面的图可能描述的是未提交或未裁决的工作"。不要在汇报里把计划中的东西说成已完成的东西。

## 3. 进度快照

```bash
python3 <skill>/scripts/evloop.py --home "$PWD/.evloop/runs/<task>" report --progress [--open]
```

- 写到运行目录的 `progress.html`（优化场景另写 `progress-process.svg` 与 `progress-caption.json`）。
- 不改动交付包、不影响审批状态，随时可以跑；快照不允许覆盖交付包文件。
- 页面包含：当前状态（场景、基线提交、保留的提交、工作区 HEAD）、下一步、AI 评审说明、最近 8 次检查记录、约定边界，以及场景专属的内容（修复的运行表、开发的构建顺序与元素覆盖、优化的过程图与路线统计）。
- 输出的 JSON 里有页面绝对路径和用于打开它的命令（`open`）。能内嵌预览就预览，否则把路径和命令交给人。

## 4. review.md：智能体的评审说明

在运行目录下写 `review.md`（纯文本或 Markdown），`report` 会把它原样放进"AI 评审 · 判断与局限"一节，并标注"由智能体撰写的解读，不是测试裁决"。没有这个文件时，页面会明确写出"本报告不评估语义覆盖度与未经验证的行为"。

建议包含：

1. **做了什么**：按提交或元素概括改动。
2. **已观察**：引用具体的尝试编号、命令结果、分数。
3. **AI 评估**：你对正确性、风险、副作用的判断及依据。
4. **未验证**：测试没覆盖的行为、环境差异、已知局限。
5. **建议**：是否建议批准，批准前人最该看哪里，后续可以加进宪法的规则。

## 5. 可读性

- 先结论后细节：第一屏就能看到状态与下一步。
- 用人能懂的词，而不是内部字段名；提交号用短哈希。
- 每个结论都能点到证据：`raw/` 日志、`attempts.jsonl`、`caption.json`。
- 页面自包含：无脚本、无外部资源、深色主题，离线可读，适合作为附件转发。
