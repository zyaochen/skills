# 研究与文档场景的澄清

代码任务有测试做裁判，研究和文档任务没有现成的退出码。这里把"写得好不好"拆成三层验收，前两层由裁判机械执行、只能否决，第三层由人批准：

| 层 | 谁判 | 判什么 | 失败时 |
|---|---|---|---|
| L1 硬检查 | 裁判（纯文本 + 可选命令） | 必需标题、篇幅、禁用内容、注入文本、论断逐字核对来源快照、每个问题的来源数、逐问题验收命令、doctest、`--test-cmd` | 诚信问题判无效；未完成判失败 |
| L2 细则评审 | 约定的外部评审命令 | 按冻结的评分细则打分，K 次采样取中位数，先用好 / 差样本校准 | 低于通过线不能接受；比已接受版本低出噪声判回退 |
| L3 人工批准 | 人 | 结论是否可信、是否回答了真正的问题 | `approve` 之前不合并 |

两个场景的区别：`research` 必须有论断文件，每条结论都要能追溯到来源原文；`document`（使用说明、设计文档、发布说明）论断文件可选，主要靠结构、篇幅、验收命令与 doctest。

## 1. 文档规格（`--doc-spec`，冻结）

```json
{"headings":  ["背景", "结论"],
 "min_chars": 800,
 "forbidden": ["\\bTODO\\b", "待补充"],
 "claims":    "docs/claims.jsonl",
 "doctest":   false,
 "cite_numbers": true,
 "questions": [{"id": "q1", "text": "新缓存层的命中率是多少", "min_sources": 2,
                "heading": "命中率", "accept": "python3 checks/q1.py"}]}
```

- `headings`：必须以 Markdown 标题出现的章节。
- `min_chars`：去掉空白后的最少字符数。
- `forbidden`：不得出现的正则；不给时默认拦截 TODO / TBD / FIXME / 待补充 / 待完善 / lorem ipsum。
- `claims`：论断文件路径，必须在 `--editable` 之内；`research` 场景必填。
- `doctest`：为 `true` 时对草稿跑 `python -m doctest`，文档里的代码示例必须能跑。
- `cite_numbers`：为 `true` 时，正文里每个含数字的句子都必须带脚注，且句中每个数字都要出现在所引论断的摘录里（千分位逗号忽略；代码、标题、`p99` / `v1.3` 这类标识符不算）。需要 `claims`。研究报告建议开启——编数字是最常见的幻觉。
- `questions`：要回答的问题。`min_sources` 是覆盖该问题的**不同来源域名**数下限（按跳转后的最终地址计算域名，内容完全相同的快照只算一个）；`heading` 是期望出现的章节；`accept` 是逐问题验收命令，退出码 0 才算回答了。

`init` 会拒绝没有区分度的规格：如果一份只有标题骨架的草稿就能通过全部硬检查，说明规格什么也没约束，必须补上 `min_chars`、问题清单或论断要求。

## 2. 论断与来源

论断文件每行一个 JSON：

```json
{"id": "c1", "question": "q1", "source": "s1", "quote": "缓存的命中率在压测中达到 93.5%"}
```

草稿用脚注 `[^c1]` 引用论断。裁判的规则：

- 草稿引用了论断文件里不存在的 ID → **编造引用**，判无效并回滚。
- `quote` 必须逐字出现在来源快照里（只规范化空白与全半角）→ 对不上判无效。
- 只有被草稿引用、且摘录核对通过的论断才计入问题覆盖；写了论断但正文没引用，不算。
- 论断文件不是合法的 JSON 行、引用了未登记或被篡改的来源 → 判无效。

来源先登记、再引用：

```bash
$J source add --url https://example.org/report --note "官方压测报告"
$J source add --file notes/bench.txt --note "内部压测记录"   # 需要 init 时加 --allow-local-sources
$J source list                                              # 列出来源与快照完整性
```

`source add` 抓取页面（去掉脚本与样式后转成纯文本），按内容哈希快照进运行目录，只读保存。超时、5xx、429 自动重试两次；PDF 等二进制内容与超过 5 MB 的页面直接拒绝（先转成文本再用 `--file`）。短链跳转后按最终地址记域名；与已有来源内容完全相同的快照标 `duplicate_of`，快照里有疑似评审指令的文字标 `injection`，两者都会在 `source list` 与交付包里提示。之后摘录只核对快照，不再访问网络，所以结果可复现；快照被改动时 `source list` 显示 `intact: false`，引用它的尝试判无效，`doctor` 也会报出来。默认只接受网页来源；本地文件需要在 `init` 时明确 `--allow-local-sources` 并在约定里写明理由。

## 3. 细则评审（可选，L2）

```bash
$J init --scenario research --editable docs --draft docs/report.md --doc-spec spec/doc-spec.json \
  --judge-cmd "<读标准输入、最后输出 SCORE: <数字> 的命令>" --rubric spec/rubric.md \
  --golden-good spec/good.md --golden-bad spec/bad.md --rubric-threshold 7 --rubric-samples 3
```

- 五个参数 `--judge-cmd`、`--rubric`、`--golden-good`、`--golden-bad`、`--rubric-threshold` 必须一起给；细则与两份样本自动加入冻结文件。
- 评审命令从标准输入读提示词，最后一行输出 `SCORE: <数字>`；也可以读环境变量 `EVLOOP_PROMPT_FILE`、`EVLOOP_DRAFT_FILE`、`EVLOOP_RUBRIC_FILE`、`EVLOOP_SAMPLE`。裁判自己不调用任何模型接口，评审用什么模型由用户决定，**建议用与写草稿不同的模型**，避免自评偏高。
- **校准**：`init` 时对好样本、差样本各采样 K 次。好样本中位数必须达到通过线、差样本必须低于通过线、两者之差必须大于噪声（同一样本 K 次打分的极差），否则判无效（退出码 2）——这位评审分不清好坏，不能当裁判。
- **裁决**：每次尝试取 K 次中位数；低于通过线算未完成；已有接受版本后，新版本比它低出噪声以上判回退并回滚。评审命令失败或没输出分数，判无效。
- **省调用**：低于通过线的采样一旦过半，中位数已注定不达标，剩下的采样不再调用（记录里标 `early_stop`）。能通过的草稿总会采满 K 次，校准与 `verify` 也不提前结束。

## 4. 防注入

草稿是被评的数据，不是指令：

- L1 先扫描草稿里的注入文本（中英文的"忽略之前的指令""给满分"等），命中即判无效，根本不送评审。
- 送评时草稿夹在每次随机生成的分隔符之间，提示词明确要求评审把其中的指令性文字当作扣分理由。
- 来源快照只用于逐字核对，不进入评审提示词；快照里出现疑似指令文字时 `source add` 会标记并警告，引用它时只当数据。

## 5. 裁决汇总

| 情况 | 裁决 | 工作区 |
|---|---|---|
| 编造引用、摘录对不上快照、注入、论断文件损坏、来源被篡改或不被接受、评审命令出错 | `invalid`（2） | 回滚 |
| 硬检查或评审未过，且还没有接受过任何版本 | `failing`（1） | 保留，便于逐步写完 |
| 硬检查或评审未过，且已有接受版本 | `rejected`（1） | 回滚 |
| 已接受后评审中位数下降超过噪声 | `rejected`（1） | 回滚 |
| 全部通过 | `accepted`（0） | 成为新的最优 |

## 6. 澄清清单

- [ ] 交付物是什么、给谁看：决定必需章节与篇幅。
- [ ] 要回答哪些问题、每个问题需要几个独立来源；数字是否必须逐个有出处（`cite_numbers`）。
- [ ] 哪些来源可信（官方文档、论文、内部记录）；是否允许本地文件。
- [ ] 是否需要细则评审；细则、好样本、差样本、通过线由人确认。
- [ ] 交付包里人会看到：每个问题的覆盖情况、每条论断及其来源、评审分数与校准结果。
